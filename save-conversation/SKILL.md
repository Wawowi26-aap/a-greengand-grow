# 收尾存档 (Save Conversation)

## 目的

解决「对话历史越长、每轮消耗的 token 越多」的问题。模型无状态，历史不会免费留在"脑子里"；
把会话的**有效内容**压缩成一份可复用的文档落盘，就能放心清空上下文，既省钱又不丢东西。

## 何时使用

- 用户说「收尾 / 存档 / 保存对话 / 保留这次内容 / 结束 / finish / wrap up / archive」等
- 一段工作告一段落，用户准备 `/clear`、`/compact` 或开启新会话之前

## 流程

### 第 1 步：梳理本次会话（不写文件，先整理）

从当前上下文提炼一份结构化摘要，**详细度要达到「下次会话凭这份文档就能直接续作，不用再翻历史」**。包含：

1. **目标** — 这次要做什么（一句话说清，含背景）
2. **已完成** — 实际做了什么、结果如何（逐项列出，标注「已验证/未验证」）
3. **关键决策** — 做了哪些选择，**每个都写理由（为什么选 A 不选 B）**
4. **产物** — 新建/修改的文件用**表格**列（完整路径 + 操作类型），跑过的关键命令**原文贴出**
5. **未完成 / 待办** — 还没做的事、下一步（明确列全，不要含糊带过）
6. **坑与注意** — 具体可操作的坑（带触发条件和解法），不是空泛的「注意安全」

禁止写成流水账或「做了若干事情」式的空话——每条都要有具体文件名、路径、命令或数值。

### 第 2 步：询问用户是否保留（必须问，不能跳过）

用 AskUserQuestion 询问「是否保留这次对话的内容？」，提供：

1. **完整存档（推荐）** — 把上面的摘要写成带日期的 Markdown，存到 `~/.claude/archive/`
2. **只存要点到记忆** — 把长期有用的结论写入 memory（用户偏好/项目状态），更新 MEMORY.md
3. **不保留** — 直接丢弃，提示可以 `/clear`

### 第 3 步：按选择执行

- **完整存档**：用 Write 工具写 `~/.claude/archive/YYYY-MM-DD-<主题>.md`。
  - 日期用今天的真实日期（从上下文获取，不要臆造）。
  - 主题取一句话概括，用中文。
  - 内容为第 1 步的结构化摘要，要写得"可续作"——下一次会话凭这份文档就能直接继续。
  - 目录不存在则先创建。写完后告知文件完整路径。
- **只存要点**：按 memory 系统规范（frontmatter + 单条事实，见系统提示中的 memory 目录）
  写入记忆文件，并在 MEMORY.md 加一行索引。只写"跨会话仍有价值"的内容，不写一次性细节。
- **不保留**：什么都不写，直接告知可以清空。

### 第 4 步：给出释放上下文的提示

无论哪种选择，最后都告诉用户：现在可用 `/clear`（清空上下文）或 `/compact`（压缩上下文）释放 token，
完整存档已（或未）落盘，不会丢失。

## 规则

- **必须先问，不能自作主张写文件或写记忆。**
- 存档目录不存在则创建；文件名日期必须是当天真实日期。
- 摘要要"可续作"，而不是流水账复述。
- **详细度硬要求**：文件路径必须完整、命令必须原文、决策必须带理由、坑必须具体可操作；不得用「处理了若干文件」「做了一些优化」这类空话。
- 不重复保存 repo / CLAUDE.md / git 里已有的信息；只保存非显而易见、会随上下文一起丢的内容。
- 存档默认路径 `~/.claude/archive/`；若用户想存到桌面，改为 `~/Desktop/对话存档/` 即可。
